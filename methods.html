Data & Methods

Where the data came from, how it was loaded into MySQL on AWS, and the decisions behind the numbers

The data

The Reporting Carrier On-Time Performance table from the US Bureau of Transportation Statistics (TranStats) has one row per domestic flight operated by large US airlines. It records scheduled and actual times, delays, cancellations, diversions and their causes. My assigned month was January 2024: one CSV of 247 MB, 547,271 rows and 110 columns.

Star schema

The data is organized as a star schema: one fact table of flight events, plus small lookup (dimension) tables that turn codes into readable names.

Dimension table Rows Joins to fact column(s)
L_AIRLINE_ID 1,665 DOT_ID_Reporting_Airline
L_AIRPORT 6,545 Origin, Dest
L_AIRPORT_ID 6,527 OriginAirportID, DestAirportID
L_CANCELATION 4 CancellationCode
L_DISTANCE_GROUP_250 11 DistanceGroup
L_WEEKDAYS 8 DayOfWeek

Every flight’s airline, origin airport and day of week found a match in its lookup table, so inner joins drop no flights.

Loading pipeline on AWS

The fact table is too large for MySQL Workbench’s import wizard, so it was loaded from a cloud machine with MySQL’s bulk loader:

  1. Created schema FAA (UTF-8) and the fact table al_perf with the course’s CreateFactTable.sql.

  2. Copied al_perf.csv to an EC2 instance with scp, installed the MySQL/MariaDB client, and ran the bulk load against the RDS endpoint. It loaded 547,271 records, the CSV’s row count minus its header:

    mysqlimport --local --compress --user=admin -p --host=<rds-endpoint> \
  --fields-terminated-by=',' --fields-optionally-enclosed-by='"' \
  --ignore-lines=1 FAA al_perf.csv

  3. Loaded the six dimension tables with Workbench’s Table Data Import Wizard.

  4. Terminated the EC2 instance (and kept the RDS database) to avoid charges.

  5. Ran the 7 queries, exported each result to CSV, and built this site from those CSVs with Quarto, pandas and Plotly. The site never connects to the database.

Data-cleaning decisions

Blank numbers become zeros. In the CSV, a cancelled flight that never left the gate has empty DepTime and DepDelay fields. mysqlimport stores an empty numeric field as 0 and raises a warning (that’s most of the ~250,000 import warnings). The database therefore says those 19,784 flights departed “0 minutes late”. For every departure-delay calculation I keep only rows with a recorded departure time, DepTime <> ''. Without that filter, airports and airlines hit hardest by cancellations would look more punctual than they were. (605 cancelled flights did leave the gate before being cancelled. They keep their real recorded delay.)

Early departures. Problem 4 says to count early departures as 0 minutes. I use GREATEST(DepDelay, 0), which equals BTS’s own DepDelayMinutes column, and apply the same rule in Problem 5 and in the site’s average-delay charts so all averages are comparable.

The header row. The course instructions run mysqlimport without --ignore-lines=1, which loads the CSV header as one junk row (Year = 0, FlightDate = the text ‘FlightDate’). I skipped it at load time. If it had been loaded, DELETE FROM al_perf WHERE Year = 0; would remove it.

What counts as a flight. BTS sets Flights = 1 on every row, including cancelled ones, so flight counts (Problems 3 and 7) use COUNT(*) over all scheduled flights.

Ties. Problems 5 and 6b use RANK(), which keeps ties rather than picking one row arbitrarily. Problem 5 had no ties. In Problem 6b, 5 airports had two reasons tied for first, giving 301 rows for 296 airports.

Verification

Every answer was recomputed independently with pandas directly from the raw CSV (not through MySQL), and the results matched exactly.

Limitations

  • One month. January has winter weather and, in 2024, an unusual safety grounding. These patterns should not be read as typical for the whole year.
  • Small samples. Averages for small airports and rare airline–airport pairs rest on very few flights. The site reports those counts alongside the averages.
  • Cause vs. coincidence. The link between carrier cancellations and the 737 MAX 9 grounding comes from timing, airline and airport patterns. The dataset has no aircraft-type column, so it can’t prove which aircraft was cancelled.
